# AERIS-10 - Editable Software Architecture Diagrams

Project AERIS-10 | Revision A | Date 2026-10-09 | Author: reconstruction team (evidence-based; nothing drawn that is not in the repository)

All diagrams are Graphviz DOT sources (edit the `.dot`, re-render with `dot -Tsvg|-Tpdf|-Tpng -Gdpi=150`). Two of them are generated by scripts in `tools/` and must not be edited by hand; re-run the script instead. Every graph carries a title block (project, drawing ID, revision, date, status, sources) and a legend node with the file:line evidence.

Status vocabulary: VERIFIED (checked against executed tool output or hardware), SOURCE-DERIVED (drawn 1:1 from repository source text), PARTIAL (source-derived but the depicted system is incomplete in the repository), CONCEPTUAL (intent only), BLOCKED - MISSING DATA (cannot be drawn from repository evidence).

## Edge / box conventions

- SD-01: solid box = module defined in repo; dashed red = instantiated without a definition; grey = Xilinx UNISIM primitive; dotted outline = defined but never instantiated. Edge label = instance name @line.
- SD-02 / SD-03 / SD-04 / SD-06: blue = present in source; orange = present but with a documented defect or source-commented placeholder; red dashed = absent from repository; grey dotted = defined/imported but not used (or UNVERIFIED).
- SD-07: solid = confirmed by a schematic net and a firmware/RTL reference; dashed = unverified (single source, anonymous net, inferred mapping, or wiring confirmed but driver/RTL broken); dotted red = missing specification / no hardware path.

## Regeneration

```sh
# from the repository root
python3 tools/gen_verilog_hierarchy.py  --rtl 9_Firmware/9_2_FPGA --out engineering/SOFTWARE_DIAGRAMS/FPGA     # exit 1 = missing module definitions exist (expected today)
python3 tools/gen_python_module_graph.py --src 9_Firmware/9_3_GUI  --out engineering/SOFTWARE_DIAGRAMS/PYTHON   # exit 1 = a file has a SyntaxError (GUI_V1.py, expected today)
for d in engineering/SOFTWARE_DIAGRAMS/*/*.dot; do for f in svg pdf png; do dot -T$f -Gdpi=150 "$d" -o "${d%.dot}.$f"; done; done
```

Tool versions used for the committed exports: Graphviz `dot` 16.1.0 (`/opt/homebrew/bin/dot`), Python 3.14.7. Both scripts are standard-library only, non-destructive, and return 2 on usage/I-O errors.

## What these diagrams do not claim

They document the software **as committed**. They do not establish that any subsystem compiles, synthesises, enumerates, or functions: the FPGA tree has 5 missing modules and no project file, the STM32 tree lacks the HAL/USB stack, and no GUI has been launched. Where a connection is shown dashed or dotted, the repository does not contain enough evidence to call it verified; the legend of each graph lists exactly what was and was not checked.
